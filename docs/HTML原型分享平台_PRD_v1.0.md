## 1. 文档说明

### 1.1 文档目标

本文档用于定义「HTML 原型分享平台」V1 版本的产品需求，重点覆盖：

1. 用户账号注册、登录、忘记密码、修改密码。
2. 团队空间、项目、文件夹、文件的层级管理。
3. 用户角色与权限控制。
4. ZIP 格式 HTML 原型包上传、解析、目录识别和在线预览。
5. Axure RP 导出 HTML ZIP 包的识别与预览，需兼容复杂动态面板和页面树。
6. 原型分享，包括团队内分享、外部链接分享。
7. V1 标注模式，包括元素尺寸、色号、间距、CSS 属性查看。
8. 预览页评论，包括点击任意区域添加评论，以及评论回复。
9. 安全、异常、验收标准。

本文档后续可直接作为开发需求输入，研发需基于本文档进行技术方案设计、数据库设计、接口设计和开发实现。

### 1.2 版本范围

| 阶段 | 版本定位 | 是否纳入本文档 |
|---|---|---|
| V1 / MVP | 账号、团队、项目、ZIP 上传、预览、权限、分享、标注、评论与回复 | 是 |
| V1.1 / 第二阶段 | 版本管理、上传历史、验收状态、批量权限 | 否，仅保留扩展方向 |
| V2 / 第三阶段 | 版本对比、DOM 评论定位、导出标注文档、SSO、通知、审计统计 | 否，仅保留扩展方向 |

### 1.3 重要决策

| 决策项 | 当前结论 |
|---|---|
| 产品形态 | 自建 Web 平台 |
| 首版登录方式 | 用户名 + 密码 |
| 用户名规则 | 英文字母或数字，长度 5 位以上，不可重复 |
| 密码规则 | 英文字母或数字，长度 6 位以上 |
| 首版上传格式 | 仅支持 ZIP |

| 文件层级 | 团队空间 → 项目 → 文件夹 / 文件 |

## 2. 产品背景

### 2.1 背景描述

当前 AI 工具和 Axure RP 等原型工具可以快速生成 HTML 高保真原型，但在企业内部协作评审时存在明显断点：

1. HTML 原型不方便安全地在线分享给企业团队成员。
2. 普通网盘只能解决文件传输，无法很好支持在线运行、权限控制、标注和评论。
3. GitHub Pages / Cloudflare Pages 等静态托管方案更适合公开访问，企业内部权限控制成本高。
4. Figma / XD 更适合设计稿，不适合直接承载 AI 或 Axure 生成的 HTML 原型。
5. 研发查看 HTML 原型时缺少类似 Figma Inspect / XD 标注的尺寸、色号、间距、字号等信息。
6. 产品、设计、研发、业务围绕同一个原型进行评审时，缺少统一的评论和反馈闭环。

因此，需要建设一个可自建、可私有化部署、面向企业内部团队使用的 HTML 原型分享、预览、权限、标注与评论平台。

### 2.2 核心问题

| 问题 | 当前影响 |
|---|---|
| HTML 原型分享不便 | 原型只能以文件形式传输，查看门槛高 |
| 缺少权限控制 | 原型可能被未授权人员访问，存在泄露风险 |
| 缺少在线预览 | 评审人员需要下载解压，本地打开容易出现资源路径问题 |
| 缺少标注 | 研发无法快速获取尺寸、颜色、字号、间距 |
| 缺少评论 | 评审意见散落在聊天工具中，不可追踪 |
| Axure HTML 包托管困难 | Axure 导出结构复杂，缺少统一预览管理平台 |

### 2.3 产品目标

V1 版本目标：

1. 建立一个可登录的企业内部 HTML 原型管理平台。
2. 支持主管理员和子管理员创建团队；支持团队内项目、文件夹管理，并上传 ZIP 格式 HTML 原型包。
3. 支持识别 ZIP 包中的 HTML 页面目录，并在线预览。
4. 支持 Axure RP 导出的 HTML ZIP 包预览，需兼容复杂动态面板和页面树。
5. 支持按团队、用户、文件进行权限控制。
6. 支持团队内分享和外部链接分享。
7. 支持原型预览页的标注模式，帮助研发查看实现信息。
8. 支持预览页点击任意区域添加评论。

## 3. 用户角色与典型场景

### 3.1 用户角色

| 用户角色 | 说明 | 核心诉求 |
|---|---|---|
| 主管理员 | 系统最高权限用户 | 管理用户、角色、团队、权限和系统数据 |
| 子管理员 | 由主管理员指定的管理用户 | 协助管理团队、用户、角色和权限 |
| 员工 | 默认注册用户 | 参与团队，按权限上传、查看、分享和评论原型 |
| 产品经理 | 业务使用角色，通常为员工或管理员 | 上传原型、组织评审、收集反馈 |
| 研发人员 | 业务使用角色，通常为员工 | 查看原型、读取标注、理解实现要求 |
| 设计/业务/管理人员 | 业务使用角色，通常为员工或外部访问者 | 查看原型、发表评论、确认方案 |
| 外部用户 | 通过分享链接访问平台的用户 | 注册/登录后查看被分享原型或加入团队 |

### 3.2 典型用户场景

#### 场景 1：产品经理上传 AI 生成的 HTML 原型

1. 产品经理登录系统。
2. 进入某个团队空间。
3. 创建项目或进入已有项目。
4. 上传 HTML 原型 ZIP 包。
5. 系统解压并识别 HTML 页面目录。
6. 产品经理在线预览原型。
7. 产品经理分享给研发和设计评审。

#### 场景 2：研发查看原型标注

1. 研发登录系统。
2. 打开被分享的原型。
3. 在预览页开启标注模式。
4. 鼠标悬停元素查看高亮。
5. 点击元素查看宽高、字号、颜色、padding、margin、元素与页面边距等信息。
6. 复制 CSS 属性或根据标注进行开发。

#### 场景 3：外部用户通过链接查看原型

1. 产品经理生成外部分享链接。
2. 分享时选择“邀请加入团队”或“仅分享文件”。
3. 外部用户打开链接。
4. 未登录则先注册或登录。
5. 系统根据分享设定执行授权。
6. 外部用户进入原型预览页查看内容。

#### 场景 4：业务人员在原型上添加评论

1. 业务人员打开原型预览页。
2. 点击页面任意区域。
3. 系统生成评论标注点。
4. 业务人员输入评论内容并保存。
5. 评论显示在页面标注点和右侧评论列表中。

## 6. 权限与角色设计

### 6.1 权限设计原则

1. 所有业务资源必须经过登录校验。
2. 团队外部用户默认不可查看团队内资源。
3. 分享链接不能绕过登录和权限校验。
4. 文件权限不继承，按资源单独配置。
5. 用户是否可新增文件需要单独配置。
6. 用户可同时属于多个团队。
7. 权限判断优先级：系统角色权限 > 团队成员身份 > 文件级权限 > 分享授权。

### 6.2 系统角色

| 角色 | 权限 |
|---|---|
| 主管理员 | 系统全部功能权限；可指定其他管理员；可指定用户角色；可新建、删除、修改团队；可分配权限；可删除用户 |
| 子管理员 | 由主管理员指定；不可指定其他管理员；可新建、删除、修改团队；可指定用户角色；可分配权限；可删除用户 |
| 员工 | 默认注册用户；不可指定管理员；不可新建、删除、修改团队 |

> 说明：团队创建权限已明确：仅主管理员和子管理员可以创建团队，普通员工不可创建团队。

### 6.3 文件级权限

| 权限 | 权限说明 | 可操作行为 |
|---|---|---|
| 查看 | 可以查看文件和预览原型 | 查看文件信息、打开预览页、查看评论和标注 |
| 编辑 | 可以修改文件信息或替换文件 | 重命名、移动、替换上传、编辑描述 |
| 删除 | 可以删除文件 | 删除文件及其解析页面 |

### 6.4 新增文件权限

| 权限项 | 说明 |
|---|---|
| 可新增文件 | 用户可在项目或文件夹下上传 ZIP 原型包 |
| 不可新增文件 | 用户不可上传新文件，只能操作被授权资源 |

| 创建团队 | 是 | 是 | 否 | 否 | 否 |
| 修改团队 | 是 | 是 | 需授权 | 否 | 否 |
| 删除团队 | 是 | 是 | 需授权 | 否 | 否 |
| 添加团队成员 | 是 | 是 | 需授权 | 否 | 否 |
| 创建项目 | 是 | 是 | 需授权 | 否 | 否 |
| 上传 ZIP | 是 | 是 | 需新增文件权限 | 否 | 否 |
| 查看文件 | 是 | 是 | 需查看权限 | 是 | 是 |

## 7. 业务流程

### 7.1 注册流程

```text
用户打开注册页
→ 输入用户名
→ 再次输入用户名
→ 输入密码
→ 点击注册
→ 系统校验用户名格式、长度、重复性
→ 系统校验两次用户名是否一致
→ 系统校验密码格式和长度
→ 注册成功
→ 默认角色为员工
→ 跳转登录页或自动登录进入首页
```

异常：

| 异常 | 提示 |
|---|---|
| 用户名为空 | 请输入用户名 |
| 用户名不足 5 位 | 用户名长度需为 5 位以上 |
| 用户名包含非字母/数字 | 用户名仅支持英文字母或数字 |
| 两次用户名不一致 | 两次输入的用户名不一致 |
| 用户名已存在 | 用户名已存在，请更换 |
| 密码为空 | 请输入密码 |
| 密码不足 6 位 | 密码长度需为 6 位以上 |
| 密码包含非字母/数字 | 密码仅支持英文字母或数字 |

### 7.2 登录流程

```text
用户打开登录页
→ 输入用户名和密码
→ 点击登录
→ 系统校验账号密码
→ 登录成功
→ 判断是否来自分享链接
    → 是：继续执行分享授权和跳转
    → 否：进入首页 / 我的团队
```

异常：

| 异常 | 提示 |
|---|---|
| 用户名为空 | 请输入用户名 |
| 密码为空 | 请输入密码 |
| 用户名不存在或密码错误 | 用户名或密码错误 |

### 7.3 忘记密码 / 重置密码流程

```text
用户在登录页点击【忘记密码】
→ 进入忘记密码页
→ 输入登录用户名
→ 点击【重置密码】
→ 系统校验用户名是否存在
→ 存在：生成符合规则的临时密码
→ 弹窗展示重置后的密码
→ 用户使用新密码登录
```

规则：

1. 重置密码通过弹窗直接告知用户。
2. 重置后的密码必须符合密码规则：英文字母或数字，长度 6 位以上。
3. 用户登录后建议提示修改密码。

异常：

| 异常 | 提示 |
|---|---|
| 用户名为空 | 请输入用户名 |
| 用户名不存在 | 用户名不存在，请检查后重新输入 |

### 7.4 修改密码流程

```text
用户进入个人账号设置页
→ 输入原密码
→ 输入新密码
→ 再次输入新密码
→ 点击确认修改
→ 校验原密码
→ 校验新密码规则
→ 校验两次新密码一致
→ 修改成功
```

异常：

| 异常 | 提示 |
|---|---|
| 原密码为空 | 请输入原密码 |
| 原密码错误 | 原密码错误 |
| 新密码为空 | 请输入新密码 |

## 8.5 ZIP 上传与 HTML 解析模块

### 8.5.1 上传范围

V1 仅支持 ZIP 文件。

| 上传类型 | V1 是否支持 | 说明 |
|---|---|---|
| ZIP | 支持 | 唯一支持格式 |
| Axure RP HTML ZIP | 支持 | 以 ZIP 包形式上传，需兼容复杂动态面板和页面树 |
| RAR | 不支持 | 后续扩展 |
| 单个 HTML | 不支持 | 后续扩展 |

### 8.5.2 上传校验

| 校验项 | 规则 |
|---|---|
| 文件类型 | 仅允许 `.zip` |
| 文件大小 | 上限 100MB，不允许超过 100MB |
| 文件名 | 不允许危险字符，建议服务端重新生成存储名 |
| 解压路径 | 必须防止 Zip Slip 路径穿越 |
| 文件内容 | 解压后识别 HTML、CSS、JS、图片等静态资源 |
| 危险文件 | 禁止服务端脚本、可执行文件被访问 |

> 文件限制已明确：ZIP 上传大小限制为 100MB；解压后文件总大小和 HTML 页面数量不设限制。

### 8.5.3 HTML 页面识别规则

1. 解压 ZIP 后递归扫描 `.html` 文件。
2. 若存在根目录 `index.html`，优先作为入口页面。
3. 若不存在根目录 `index.html`，但存在其他 `index.html`，选择层级最浅的作为入口。
4. 若不存在任何 `index.html`，选择扫描到的第一个 HTML 页面作为入口，并允许用户后续手动切换。
5. 所有 HTML 页面需要按目录结构生成页面目录树。
6. 原始资源相对路径需保持可用。
7. Axure RP 导出的页面需保持原页面跳转、页面树、复杂动态面板、图片和脚本加载可用。

### 8.5.4 解析状态

| 状态 | 说明 |
|---|---|
| 解析中 | ZIP 已上传，系统正在解压和扫描 |
| 解析成功 | 已识别 HTML 页面，可预览 |
| 解析失败 | 解压失败、无 HTML、存在安全风险等 |

### 8.5.5 验收标准

1. 用户只能上传 ZIP 文件。
2. 上传非 ZIP 文件时系统拒绝并提示。
3. ZIP 包中存在 HTML 时，系统可识别页面目录。
4. ZIP 包中无 HTML 时，系统提示解析失败。
5. Axure RP 导出的复杂 HTML ZIP 包可上传并预览，包括页面树、动态面板、页面跳转、图片和脚本资源。
6. 解压后原型中的 CSS、JS、图片资源可以正常加载。
7. 页面目录点击后可切换预览页面。

4. 已生成的分享链接必须支持撤销。
5. 链接被撤销后，后续访问链接时提示“链接已失效”。
6. 链接撤销不影响用户此前已获得的团队成员身份；是否同步移除文件授权由产品后续确认，V1 建议仅让链接本身失效。

#### 验收标准

1. 分享链接未登录访问时跳转登录/注册页。
2. 登录后根据分享设定执行授权。
3. “邀请加入团队”模式下，用户加入团队。
4. “仅分享文件”模式下，用户不加入团队，但可以访问该文件。
5. 分享链接不能让用户访问未授权文件。
6. 分享链接过期后不可继续访问。
7. 分享链接撤销后不可继续访问。

### 8.8.2 交互规则

#### 8.8.2.1 基础交互

1. 默认关闭标注模式。
2. 用户点击“实时标注”开关后开启。
3. 开启后，鼠标悬停元素显示蓝色描边与高亮。
4. 点击元素后锁定选中，描边变绿，描外侧出现 4 条距离标尺与最近兄弟连线。

8. 标注模式不应影响原型页面正常滚动和浏览。

#### 8.8.2.2 实时标注交互（V1 强化）

### 8.8.4 验收标准

#### 基础标注能力

1. 开启标注模式后，鼠标悬停元素有明显高亮。
2. 点击元素后可显示元素尺寸和样式属性。
3. 颜色可识别并展示。
4. padding、margin、font-size 等属性展示正确。
5. 元素与页面边界距离展示正确。
6. 可复制 CSS。
7. 关闭标注模式后页面恢复正常预览。

#### 实时标注能力（V1 强化）

1. 开启实时标注后，鼠标 hover 任意预览元素，能实时看到 4 条距离标尺（顶/底/左/右）。
2. 实时显示当前元素到预览画布 4 边距离，数值精确到 2 位小数。
3. 实时显示当前元素到最近兄弟元素的距离，含方向标识（上 / 下 / 左 / 右）与兄弟 tag + class 信息。
4. 属性信息卡中需包含：tag/class/id、宽、高、X、Y、字号、圆角、4 边距离、距最近兄弟距离。
5. 属性信息卡“样式规格”区域需完整展示：字体、字重、字号、文字颜色（RGB+HEX）、背景颜色（RGB+HEX）。
6. 鼠标点击元素后，选中状态锁定，描边由蓝变绿，再次点击同一元素取消锁定。
7. 标注模式下按 `Tab` 键可跳到下一个元素；按 `Shift + Tab` 跳到上一个元素；跳到后自动滚动到可见区域。
8. 标注模式下按 `Esc` 键退出标注，描边、标尺、属性卡、兄弟连线、提示条全部隐藏。
9. 开启或切换缩放（60% ~ 200%）时，当前选中的元素距离值与标尺位置应随缩放重新计算，逻辑坐标保持稳定。
10. 实时标注模式与评论模式互斥，同时只能开启一个。
11. 缩放/拖动过程中，标尺与属性卡不得出现明显闪动或错位。
12. 所有距离数值精确到 2 位小数（如 `100.00`、`520.00`）。

### 8.8.5 实时标注强化（V1 增强需求）

> 本节作为 V1 实时标注能力的独立需求规格，不重复 8.8.1~8.8.4 中已定义的内容。

#### 背景

V1 原始标注能力（8.8）仅提供“点击查看元素 CSS”能力，未提供原型设计场景中**最常被研发调用的两类信息**：

1. 当前元素到画布四边边界的距离（用于验证设计稿布局是否合规）。
2. 当前元素与周围兄弟元素之间的距离（用于验证组件间是否“画得对、压得匀”）。

本条增强需求将这两项能力从“未覆盖”提升为“实时可见、跳动可看”，需在本期 V1 交付。

#### 功能定义

**F1｜距画布 4 边距离**

- **定义**：实时计算当前选中元素到预览画布（`frame-wrapper`）上、下、左、右 4 条边界的距离。
- **展示位置**：在元素 4 条边的外侧各画 1 条带端点的标尺线 + 1 个文本标签。
- **计算公式**：
  - `top`    = `element.top - frameWrapper.top`
  - `bottom` = `frameWrapper.bottom - element.bottom`
  - `left`   = `element.left - frameWrapper.left`
  - `right`  = `frameWrapper.right - element.right`
- **精度**：2 位小数（`100.00`、`520.00`）。

**F2｜距最近兄弟元素距离**

- **定义**：实时计算当前元素与同父级、距离最近、且与当前元素在**主轴方向不重叠**的兄弟元素之间的距离。
- **方向判断**：从 4 个方向（top / bottom / left / right）选距离最近的一个；同距时优先 top > left > right > bottom。
- **展示位置**：画 1 条“当前元素中心点 → 兄弟元素中心点”连线 + 1 个带方向箭头的文本标签。
- **文本格式**：`{distance}px · {↑|↓|←|→} {siblingTag}.{siblingClassName}`。
- **无兄弟时**：属性卡“最近兄弟”区域显示为“—”。

**F3｜实时交互引擎**

- **F3.1 Hover 触发**：鼠标移到元素上时实时刷新距离数据与渲染。
- **F3.2 点击锁定**：点击元素后选中状态锁定，描边由蓝色（#667eea）变为绿色（#22c55e）；再次点击取消锁定。
- **F3.3 Tab 跳转**：在标注模式下按 `Tab` 依次跳到下一个有实体尺寸的节点；按 `Shift + Tab` 反向跳转。跳转后高亮、属性卡、距离标尺重绘。
- **F3.4 Esc 退出**：按 `Esc` 键关闭实时标注模式，描边、标尺、属性卡、兄弟连线、顶部提示条全部隐藏。
- **F3.5 缩放适配**：缩放在 60% ~ 200% 范围内调整时，实时重算所有坐标（逻辑坐标除以 `scale`），保证距离值始终表示元素的原始设计尺寸。

**F4｜字体与颜色规格（V1.0.2 增强）**

开启实时标注后，在 hover 与选中锁定两种状态下，属性信息卡内均需完整呈现当前元素的 font 规格与 color 规格，供研发与设计者快速核验设计还原度。

**F4.1｜font 字体规格**

| 字段 | 含义 | 数据来源 | 展示格式 |
|---|---|---|---|
| 字体 | font-family | `getComputedStyle(el).fontFamily` | 保留完整 font-family 声明，截取首个字体名展示。例：`PingFang SC, Microsoft YaHei` → 主展示为 `PingFang SC` |
| 字重 | font-weight | `getComputedStyle(el).fontWeight` | 100~900 数值时直接显示；为 `normal`/`bold`/`lighter`/`bolder` 时同时显示语义与换算值（例：`bold (700)`） |
| 字号 | font-size | `getComputedStyle(el).fontSize` | 原样输出，如 `14px`、`1.2rem`，统一保留计算后的实际 px 值 |

**F4.2｜color 颜色规格**

| 字段 | 含义 | 数据来源 | 展示格式 |
|---|---|---|---|
| 文字颜色 | text color | `getComputedStyle(el).color` | 同时展示 RGB 与 HEX。例：`rgb(255, 90, 122)` ⇄ `#FF5A7A` |
| 背景颜色 | background color | `getComputedStyle(el).backgroundColor` | 同样同时展示 RGB 与 HEX；`transparent / rgba(0,0,0,0)` 时展示为 `透明` |

**F4.3｜展示与交互**

1. 属性信息卡“自身信息”区域拆为两个分组：“尺寸位置”与“样式规格”。
2. 样式规格中需同时呈现：字体、字重、字号、文字颜色（RGB+HEX）、背景颜色（RGB+HEX）。
3. RGB 与 HEX 并排展示，HEX 转为大写，保留 # 前缀。例：`rgb(255, 90, 122) · #FF5A7A`。
4. 颜色色块：文字颜色与背景颜色各在文字左侧渲染 12×12 的颜色小色块，与取色器颜色一致。
5. 字体为系统默认栈时（如 `-apple-system, BlinkMacSystemFont, ...`）需主动折叠为 `System UI` 展示，避免换行造成信息卡高度跳变。
6. 当 `color` / `backgroundColor` 为 `rgba(...)` 且 alpha ≠ 1 时，需在 HEX 展示为 `#XXXXXX (α=0.xx)`，提醒使用者存在透明度。

#### UI 规格

- **高亮框**：1.5px 主色边框 + 10% 主色背景填充 + 4 个角标；锁定态边框变 #22c55e。
- **距离标尺**：粉红色（#ff5a7a）渐变线，两端带短刻度，标签背景同色。
- **属性信息卡**：
  - 默认位置：选中元素右上角偏移 16px。
  - 翻面规则：超出画布右边界则翻到左上角，超出底边界则上移避让。
  - 信息分 5 段：标题区 / 距画布 4 边 / 尺寸位置 / 样式规格（font + color） / 最近兄弟。
  - 样式规格中，字体、字重、字号为一行展示；文字颜色与背景颜色以 `RGB · HEX` 格式 + 颜色色块同排展示。
  - 底部包含操作提示：“点击锁定 · `Tab` 跳到下一个 · `Esc` 退出”。
- **顶部提示条**：开启标注模式后顶部居中显示，胶囊形状，主色背景，文案包含 `Tab` 与 `Esc` 快捷键提示。
- **按钮文本**：工具栏按钮文案为“🔍 实时标注”（原“标注模式”调整为“实时标注”以表明能力增强）。

#### 状态与互斥

| 模式 | 互斥 | 互锁 |
|---|---|---|
| 实时标注 | 与评论模式互斥 | 开启实时标注时自动关闭评论模式 |
| 评论模式 | 与实时标注互斥 | 开启评论模式时自动关闭实时标注 |

进入实时标注模式时，重置选中态、锁定态与 tab 列表；退出时清理所有渲染节点与事件订阅。

#### 验收标准

1. 打开预览页 → 默认处于实时标注模式（按 PRD 8.8.2 调整为“开含状态”补充说明，本期 V1 默认开启）。
2. 鼠标 hover 任意预览元素 → 4 条距离标尺 + 兄弟连线 + 属性卡能实时出现并包含完整信息。
3. 所有距离数值精确到 2 位小数，如 `100.00`、`520.00`。
4. 点击元素 → 高亮变绿、属性卡与标尺保留，标尺与高亮定位准确。
5. 点击另一处空白区域或同一元素 → 锁定态取消，高亮还原为 hover 态。
6. `Tab` 键 → 跳到下一个有实体尺寸的节点（深度优先顺序），高亮与属性卡重绘。
7. `Shift + Tab` → 跳到上一个节点。
8. `Esc` → 退出实时标注，所有标注层隐藏，工具栏按钮 active 状态被移除。
9. 缩放/设备视口切换时，当前选中元素的距离标尺与高亮位置自动重算，不错位。
10. 实时标注模式下不能同时开启评论模式，反之亦然。
11. 顶部提示条在开启实时标注时出现，退出后隐藏。
12. hover 任意元素时，属性信息卡“样式规格”区域中字体、字重、字号需与元素 computed style 一致。
13. hover 任意元素时，文字颜色与背景颜色需同时展示 RGB 与 HEX 两种格式。
14. RGB 与 HEX 并排展示，HEX 转大写且保留 # 前缀。例：`rgb(255, 90, 122) · #FF5A7A`。
15. 颜色为 `rgba(..., 0.xx)` 且 alpha ≠ 1 时，HEX 展示为 `#XXXXXX (α=0.xx)`，提醒使用者存在透明度。
16. 文字颜色与背景颜色在属性卡中需以颜色色块预览，色块颜色与取色器颜色一致。
17. 字体为系统默认栈时需折叠为 `System UI` 展示，避免信息卡高度跳变。

- CSS 选择器一键复制 — 留 V1.1 评估。

## 8.9 评论模块

### 8.9.1 评论能力

V1 支持基础评论：

1. 用户在原型预览页点击任意区域添加评论。
2. 评论绑定当前 HTML 页面。
3. 评论绑定点击位置坐标。
4. 评论保存后在页面中显示评论标注点。
5. 右侧展示评论列表。
6. 点击评论点可查看评论内容。
7. 点击评论列表可定位页面对应位置。
8. 用户可对已有评论进行回复。
9. 评论回复展示在对应评论下方，形成简单会话。

### 8.9.2 评论字段

| 字段 | 说明 |
|---|---|
| 评论 ID | 系统生成 |
| 文件 ID | 所属原型文件 |
| 页面 ID | 所属 HTML 页面 |
| 坐标 X | 点击位置 X 坐标 |
| 坐标 Y | 点击位置 Y 坐标 |
| 评论内容 | 用户输入文本 |
| 评论人 | 当前用户 |
| 创建时间 | 系统记录 |

#### 评论回复字段

| 字段 | 说明 |
|---|---|
| 回复 ID | 系统生成 |
| 评论 ID | 所属主评论 |
| 回复内容 | 用户输入文本 |
| 回复人 | 当前用户 |
| 创建时间 | 系统记录 |

### 8.9.3 评论回复

回复流程：

```text
用户点击某条评论
→ 点击【回复】
→ 输入回复内容
→ 保存回复
→ 回复显示在该评论下方
```

回复规则：

1. 回复内容不能为空。
2. 回复内容需做 XSS 防护。
3. 有评论查看权限的用户可查看回复。
4. 具备评论权限的用户可回复评论。
5. V1 不需要评论解决状态。
6. V1 不需要评论通知。

### 8.9.4 规则

1. 评论内容不能为空。
2. 评论内容需做 XSS 防护。
3. 只有有查看权限的用户才可查看评论。
4. 是否允许仅查看用户评论，按分享权限配置；建议 V1 中“可评论”作为独立权限。
5. V1 支持评论回复。
6. V1 不支持评论解决状态和评论通知。

### 8.9.5 验收标准

1. 用户可在页面任意位置添加评论。
2. 评论点显示位置与点击位置基本一致。
3. 评论列表可显示评论内容、评论人和时间。
4. 切换 HTML 页面时，仅显示当前页面评论。
5. 用户可对评论进行回复。
6. 回复内容显示在对应评论下方。
7. V1 不展示评论解决状态。
8. V1 不发送评论通知。
9. 评论和回复内容中的脚本不会执行。

## 10. 非功能需求

### 10.1 安全需求

1. 密码必须加密存储，不允许明文存储。
2. 所有业务接口必须校验登录态。
3. 文件访问必须经过鉴权，不允许直接暴露静态路径绕过权限。
4. 分享链接必须登录后才能访问。
5. 分享 token 需具备不可预测性。
6. ZIP 解压必须防止 Zip Slip 路径穿越。
7. 解压后的危险文件不可被执行或访问。
8. iframe 预览需要 sandbox 隔离。
9. 评论和回复内容必须做 XSS 过滤。
10. 上传文件大小、数量、解压后总大小需做限制。

### 10.2 性能需求

1. 普通页面列表加载时间建议 ≤ 2 秒。
2. ZIP 上传后解析过程可异步处理，解析中展示状态。
3. 原型页面预览加载速度取决于文件大小，但平台自身不应阻塞。
4. 页面目录树在 500 个 HTML 页面以内应可正常展示和搜索。

### 10.3 兼容性需求

1. 支持主流 Chrome / Edge 浏览器。
2. 预览页面需兼容常规 HTML、CSS、JS 静态原型。
3. Axure RP 导出 HTML 包需支持复杂动态面板和页面树的预览。

### 10.4 可配置项建议

| 配置项 | 默认建议 |
|---|---|
| ZIP 最大上传大小 | 100MB |
| 解压后最大总大小 | 不限制 |
| HTML 页面数量上限 | 不限制 |
| 单个团队最大成员数 | 不限制 |
| 单项目最大文件数 | 不限制 |
| 分享链接有效期 | 生成链接时可自定义有效期天数 |
| 分享链接撤销 | 支持撤销，撤销后链接失效 |

## 13. 风险与注意事项

| 风险 | 说明 | 建议 |
|---|---|---|
| HTML 原型安全风险 | 上传 HTML 可能包含恶意 JS | iframe sandbox + 资源鉴权 + 禁止危险能力 |
| ZIP 解压风险 | 可能存在路径穿越或炸弹包 | 限制大小、数量、路径、安全扫描 |
| Axure 兼容复杂 | Axure 导出结构复杂，动态面板和页面树兼容成本高 | V1 明确要求兼容复杂动态面板和页面树，需作为专项技术验证 |
| 标注实现复杂 | iframe 内 DOM 获取和 overlay 可能复杂 | 优先实现同源预览和 inspector 注入 |
| 权限模型复杂 | 文件级独立权限会增加管理成本 | V1 先做清晰 ACL，后续再做批量权限 |
| 忘记密码安全性弱 | 直接弹窗展示重置密码安全性较低 | 按当前需求实现，后续建议引入邮箱/手机验证 |

## 17. 结论

HTML 原型分享平台 V1 的核心不是做一个普通文件网盘，而是面向产品研发协作的“HTML 原型托管 + 权限分享 + 在线预览 + 标注 + 评论”平台。

V1 必须优先保证四件事：

1. **安全可控**：登录、团队、权限、分享都不能绕过鉴权。
2. **原型可用**：ZIP 上传后 HTML 页面、CSS、JS、图片能正常预览。
3. **研发可交付**：标注模式能提供尺寸、色号、间距、CSS 等信息。
4. **评审可闭环**：评论能绑定页面位置，形成反馈记录。

研发团队可基于本文档开展技术设计、数据库设计、接口拆分、排期和测试用例编写。
