### 2.2 实时标注（Inspect）增强

#### 补充 inspect 属性
原先 inspect 卡片缺失字体和色值信息，本次补充：

- Font Family
- Font Size
- Font Weight
- Line Height
- Letter Spacing
- 文字色（HEX / RGB）
- 背景色（HEX / RGB）
- 边框色（HEX / RGB）
- 颜色色块预览

对应文件：
- `frontend/public/prototype-assets/inspector.js`

#### 三种模式交互策略落地
通过 postMessage 建立模式协议：

- `inspect`：完全禁止业务点击，只保留选元素/锁定/Tab/Esc
- `comment`：允许滚动，但禁止页面跳转/按钮点击/表单提交
- `normal`：恢复页面原始行为

对应文件：
- `frontend/src/pages/projects/PrototypeViewerPage.tsx`
- `frontend/public/prototype-assets/inspector.js`

#### 修复 inspect 弹框被裁剪
问题：浮层挂在 `overflow: hidden` 的父容器中，导致【色值】等内容被截断。

修复方案：
- 将 iframe 包装层拆成：
  - `.viewer-frame-shell`（外层，overflow visible）
  - `.viewer-frame-viewport`（内层，负责圆角和内容裁剪）
- 浮层增加最大高度和内部滚动

对应文件：
- `frontend/src/pages/projects/PrototypeViewerPage.tsx`
- `frontend/src/styles/global.css`

### 2.3 评论模式新增标注流程补齐

原先评论模式下：
- 点击页面只有提示信息
- 不会真正创建 marker / comment

本次增强后支持：

1. 开启评论模式
2. 点击页面任意位置
3. 生成橙色草稿标记 `?`
4. 右侧输入评论
5. 点击“创建标注”
6. 生成正式 marker 与对应评论卡片

另外还支持：
- 取消草稿标记
- 点击已有标注进行回复
- 回复追加到对应评论下

对应文件：
- `frontend/src/pages/projects/PrototypeViewerPage.tsx`
- `frontend/src/styles/global.css`

### 2.4 修复评论模式点击无效

问题原因：
- `.viewer-overlay-layer` 默认 `pointer-events: none`
- 评论模式下点击穿透到 iframe，外层收不到点击事件

修复：
- 评论模式增加 `is-comment-mode`
- 仅在评论模式时 `pointer-events: auto`

结果：评论模式下可正常点击页面创建标注。

---

### 2.5 修复评论串页问题

测试 `统一账户流水查询.html` 时，新增评论 `8888` 后，错误地出现了其他页面的“张三评论”和回复。

根因：
- 原评论匹配逻辑只按 `marker 编号`
- 不同页面若都有 `#1/#2`，评论会串页

修复：
- 评论增加 `pageId`
- 渲染评论列表时同时按：
  - 当前 `pageId`
  - 当前 marker 集合

结果：不同页面之间的评论不会再串联。

### 2.6 数据模型重构（为后端持久化预留）

#### 模型升级目标
把评论系统从“前端 demo 结构”升级到“可对接后端的数据结构”。

#### 新关系模型

- `ViewerMarker.commentId`
- `ViewerComment.markerId`
- `ViewerCommentReply.commentId`

即：
- 一个 marker 对应一个主 comment
- reply 归属于 commentId

#### 新增标准 payload
定义 `ViewerAnnotationPayload`，打包：
- fileId
- pageId
- marker
- comment
- replies

并新增 `buildAnnotationPayload()`，作为后续后端接口接入时的统一出参结构。

对应文件：
- `frontend/src/store/viewerMockData.ts`
- `frontend/src/pages/projects/PrototypeViewerPage.tsx`
