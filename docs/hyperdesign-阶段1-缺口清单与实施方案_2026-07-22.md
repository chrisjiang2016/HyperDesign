## 二、当前缺口判断

本阶段只给出工程级缺口，不展开逐文件考古。

### A. 产品阶段缺口

#### Sprint 0～4
- 后端接口面基本齐。
- 前端虽可 build，但不能仅以“能构建”视为“功能完整恢复”。
- 需要逐主线重新验收：认证、团队、项目、文件目录、文件权限、Viewer 入口。

#### Sprint 5
- 评论 / 回复 / 标注锚点能力在历史记录中已完成。
- 但当前前端是否完整接回真实协作链路，仍需单独核验。
- 这部分应作为独立主线处理，不与基础壳层重构混做。

#### Sprint 6
- 当前主要缺口不在“文档有没有写”，而在“功能是否真正对齐并验收”。
- 明确未完成项：
  1. Playwright 21 个用例的真实通过验证
  2. 安全测试执行
  3. Docker Compose / 部署材料
  4. 前端统一到新的设计规范

### B. 前端缺口

#### 1. 设计系统缺口
- 当前已接 Ant Design 主题，但还没有证明整站已经统一到“新的设计规范”。
- 需要先补一层新的前端规范基座：
  - design token
  - 页面栅格与 shell
  - 导航、表格、详情页、空态、表单、状态反馈统一规范

#### 2. 页面完整性缺口
- 需要逐块核实并补齐以下页面主线：
  - 认证页
  - 团队页 / 团队详情
  - 项目详情
  - Viewer
  - 分享相关页面 / 入口

#### 3. 测试对齐缺口
- 即使当前页面能 build，也不代表已有 E2E 用例仍然可跑。
- 需要补齐 `data-testid`、稳定选择器、可等待状态与测试夹具契约。

### C. 工程化缺口
- 安全测试尚未执行。
- 容器化与部署物料尚未落地。
- 前端构建虽然通过，但仍存在大包 warning，需要在 Sprint 6 收尾阶段处理。

## 三、分阶段实施方案

后续严格按“只读当前阶段所需文件 -> 实现 -> 写文件 -> build 验证”的节奏执行。

### 阶段 2：前端新设计规范基座
目标：先立新 UI 规范，不直接把所有业务逻辑一起搅进去。

视觉基线：`HTML prototype/prototype` 下的原型页。后续 2B 及阶段 3 的页面实现，必须以该目录中的实际布局、层级、状态和交互样式为准，不以通用 SaaS 模板替代原型设计。

输出物：
- 主题 token
- 全局布局规范
- 导航 / 页头 / 内容区骨架
- 通用空态 / Loading / 错误态组件
- 表单与详情页基础样式

验证：
- frontend `npm run build`

#### 阶段 3D 完成记录（2026-07-22）
- 核对后端已具备真实分享能力：创建、列表、撤销、令牌校验、登录后接受分享；服务端限制为文件上传者/编辑者管理、1–30 天有效期、登录接受后只读授权。
- 前端补齐分享 API 请求封装：分享记录、创建、撤销、校验和接受。
- Viewer 的分享入口已接入真实分享管理弹窗：可创建并复制链接、查看有效期和接受次数、撤销有效链接；入口严格受文件 `canEdit` 权限控制。
- 新增 `/shares/:token` 接受分享页：先校验链接，再要求用户登录，成功接受后进入既有受控 Viewer；无效、过期或撤销链接展示统一错误态。
- 项目详情的分享入口按真实契约改为文件级：仅解析成功且有编辑权限的原型文件可进入分享管理，不虚构“整项目分享”能力。
- 当前后端不提供匿名预览、密码、可评论分享或自定义访问次数限制，前端未伪造这些能力。
- 验证：frontend `npm run build` 通过；分享接受、撤销后访问失效的浏览器级回归留到 Sprint 6 E2E 验收块。

### 阶段 3：核心业务页逐主线接回
按以下顺序拆块推进：

1. 认证主线
- 登录 / 注册 / 忘记密码 / 会话恢复

2. 团队与项目主线
- 工作台
- 团队列表 / 团队详情
- 项目详情 / 文件目录 / 文件上传与状态展示

3. 权限主线
- 团队成员上传权限
- 项目可见范围
- 文件级权限管理

4. Viewer 与协作主线
- 页面目录
- 预览入口
- Inspector
- 评论 / 回复 / 标注状态

5. 分享主线
- 分享创建
- 接受分享
- 撤销分享

每一主线规则：
- 每次只推进一个主线块
- 每完成一块立即 build
- 不跨主线大范围扩读

## 四、执行约束

本项目后续执行必须遵守：

1. 不一轮读取过多文件。
2. 每完成一块就立刻写文件。
3. 每完成一块就立刻 build 验证。
4. 先基座、后主线、再测试、最后部署。
5. 前端样式必须统一到新的设计规范，不以“旧页面恢复可用”作为完成标准。
